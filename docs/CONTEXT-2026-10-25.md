## The quirk: a duplicate branch, and a second checkout of main

Two related traps cost time today. Both are recorded here so they are not
repeated.

**1. `main` was not where the work looked like it was.** The primary checkout
`/root/gridiron-physics` was sitting on `feat/autonomous-db-passing`, while
`main` was checked out in a separate worktree `/root/gridiron-main-merge`.
Worktrees share one object database and one set of branch refs, so a merge and
push performed in the worktree genuinely updated `main` in the primary repo
and on the remote. But the primary working directory kept the feature branch
checked out, so the files on disk did not show the merge. This made a correct
push look like a no-op. Plain `git checkout main` in the primary is also
refused with "'main' is already checked out at ...", which needs
`--ignore-other-worktrees`.

Resolution: the worktree was removed after restoring its contents, and
`/root/gridiron-physics` is now the single `main` checkout.

**2. The "separate branch" was a parallel copy of PR 22, not new work.**
`feat/autonomous-db-passing` forked from `main` at `07205c6`, which is before
PR 22 merged at `dab3fc5`. The uncommitted passing work in the primary checkout
was therefore written against a tree that never saw PR 22, and it duplicated
that deliverable rather than extending it.

Evidence:

- `docs/AUTONOMOUS-STAGE-ONE-SPEC-v1.md` is byte-identical on both
  (`dd95f1e4`). One spec drove both attempts.
- `engine/autonomous-run.js` is 908 lines on the branch and 913 on `main`. The
  difference is passing ratings added inline plus one removed helper, not a
  different design.
- The passing module differs in shape: the branch has
  `engine/autonomous-pass.js` (790 lines, `simulateAutonomousPass`), while
  `main` has `engine/autonomous/passing.js` (1005 lines,
  `simulatePassPlay` / `createPassRoster`) integrated with
  `engine/autonomous/{results,schema,simulator}.js`.
- `main`'s version is the complete one and is the version covered by the nine
  passing and acceptance suites.

The work was preserved rather than discarded: `f17f49f` on
`wip/autonomous-pass-work`, pushed to the remote. It carries no unique
deliverable and exists only so nothing was lost in the cleanup. Recommendation:
delete it.

### Defensive-back movement follow-up

After the initial Stage One review branch was published, commit `b42fc85`
(`Improve autonomous run support recognition`) added role-specific defensive
back run reads to `feat/autonomous-stage-one`. It preserves corner leverage
and safety depth until an observable handoff or line-flow cue, applies a

error slightly regressed from 0.8152 m to 0.8223 m. Full cohort results and

`docs/evidence/autonomous-acceptance/bdb53-db-run-support.json` and
`docs/AUTONOMOUS-STAGE-ONE-REPORT-2026-10-25.md`.

### PR #22 review findings

The PR received a changes-needed review at commit `77b813e` before it was
merged at `dab3fc5`. The review raised four blocking correctness issues:

1. `yardline_100` is distance to the opponent's goal, but the adapter passed
   it as absolute world X for both offense directions; direction `+1` needs
   the mirrored X coordinate and mirrored goal-line tests.
2. Interception returns move opposite the original offense direction, while
   touchdown/safety checks still use that original direction. Score ownership
   must follow the live carrier; test pick-six outcomes in both orientations.
3. Pass catch candidates include the QB and offensive linemen. Ordinary
   forward-pass catches must be limited to eligible players, with near-ball
   ineligible-player fixtures.
4. The public simulator records a failed reconciliation in diagnostics but
   still returns a complete result. Reconciliation failure must fail closed,
   with mutation tests for whistle, frame stride and ball holder.

The review also cautioned against claiming NFL-like/full-game realism: rushing
gains were compressed, pass gains/TDs too high, sacks absent, and movement
fidelity behind the constant-velocity baseline. The review was attached to an
older commit; resolution of these four findings in the merged tree was not
verified as part of reading the comments. At the time this note was appended,
the primary checkout has uncommitted changes in
`engine/autonomous/passing.js`, `engine/autonomous/simulator.js` and
`test/autonomous-results.mjs` on `fix/autonomous-review-findings`; preserve
those changes and verify them before treating the findings as resolved.
