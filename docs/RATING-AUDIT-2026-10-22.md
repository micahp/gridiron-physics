# Rating audit: all 35 player ratings (NE vs CHI, 2026 Week 7 snapshot)

Scope: the 35 attributes in `data/teams/matchup-2026-10-22.json` (166 players: NE 84, CHI 82), generated by
`pipeline/ratings.py` and read by `engine/play.js` and `engine/world.js` on the free-run/pass physics branch
(`origin/feat/free-run-pass-physics`, 7385acb). The tables below come from `scripts/rating_audit.mjs`, which checks
every engine citation against the source line and refuses to render if a cited line no longer contains the expected
token. The probe results that test these ratings are in `docs/RATING-PROBE-2026-10-22.md`.

## Counts

- Class (intended purpose): 5 physical (ACC, AGI, JMP, SPD, STR), 2 physical-health (INJ, STA), 2 decision (AWR, PRC),
  26 football skill.
- Read by the engine: 16 (AGI, AWR, BSH, BTK, CIT, CTH, ELU, FMV, KPW, PBK, PMV, RBK, STR, TAK, THA, THP).
- Not read by the engine (generated-unused): 19 (ACC, BCV, CAR, IBL, INJ, JMP, KAC, MCV, POW, PRC, PRS, PUR, RET,
  RTE, SPC, SPD, STA, TRK, ZCV). The static check is a grep of the engine; the probe null test confirms that changing
  any of the 19 leaves every event and end state unchanged on 200 pass plays (0 changes for each).
- Validation: no rating is validated against outcomes anywhere in the repo. `docs/RATINGS.md:27` cites Samozino et
  al. (2016) for the sprint model, which is literature support for the model's form, not for these ratings.
  `OvrCalibration` (`pipeline/ratings.py:461`) calibrates the overall rating to a league pass, not the attributes.

## Findings that change what the ratings do

1. **Sack odds read the quarterback's pass blocking, not the blocker's.** `engine/play.js:1634` computes
   `sackOdds = clamp(0.5 + (PMV_defender − st.qb.R.PBK) × 0.006, 0.25, 0.78)`. Every QB in the snapshot has
   PBK = 48 (7 of 7), an off-position placeholder with confidence 0.15. Sacks therefore never depend on an offensive
   lineman, and the only PBK that matters is a placeholder. The probe could not exercise this path: no sack occurred
   in any probe scenario (see the probe report).
2. **Defender interception ability is a placeholder.** `engine/play.js:1223` reads `CIT` for the nearest defender.
   Every CB, S, LB and EDGE (64 of 64) carries CIT = 48 at confidence 0.15. IDL and OL take the 42 default from the
   same code path (`pipeline/ratings.py:562–565`). CIT is only estimated for WR and TE (`ratings.py:591`), and the
   engine never reads it for a receiver. The engine's use of CIT for defenders is not documented in `docs/RATINGS.md`.
3. **Throw accuracy is inert in the engine.** `engine/play.js:1198` sets the aim error to
   `(100 − THA)/100` scaled by 0.25 m, so the standard deviation of the aim error is 2.3 cm at THA 91 and 12.5 cm at
   THA 50. A receiver can reach a ball within his body radius plus 1.6 m (`play.js:1218`), so no THA value in the
   snapshot changes an outcome through this term.
4. **Two engine maxima hide ratings below the max.** Tackle odds use `max(BTK, ELU)` (`play.js:359, 368, 374`), so BTK
   has no effect while it sits below ELU. Line 496 uses `max(ELU, AGI)`, so ELU has no effect while it sits below AGI.
   Henderson (NE RB) has ELU 76 and AGI 79, so his BTK at −10 changes nothing, and his ELU at −5 and at −10 give
   identical results.
5. **Derived ratings carry the placeholder confidence.** Only values produced through `R()` in `skill_ratings`
   (`pipeline/ratings.py:545`) record a confidence. Formula-derived values (WR and TE BTK, RB RTE = CTH − 8, CB CTH =
   MCV − 14, TRK, RET, PRS) therefore read confidence 0.15 like the true placeholders. Anything that treats confidence
   0.15 as "no evidence" will mislabel them.
6. **The physical body is mostly imputed.** The 40-yard time is imputed for 50 of 84 NE players (60%) and 40 of 82 CHI
   players (49%). The imputed value carries the forty regression residual SD by position: CB 0.096 s, WR 0.099 s, S
   0.102 s, RB 0.104 s, TE 0.132 s, EDGE 0.128 s, LB 0.130 s, IDL 0.150 s, QB 0.172 s, OT 0.172 s, IOL 0.174 s. All six
   combine drills are imputed for Drake Maye, so his `vmax`, `drive` and `alat` come from regression estimates.
   `ACC` is derived from the same 40 through the sprint model, so ACC inherits the same uncertainty.
7. **SPD displays a rating the engine does not use.** The simulator takes `vmax` from the 40 directly
   (`pipeline/ratings.py:519`, `physics.vmax`). The SPD attribute only drives displays and the RET and POW formulas.
8. **Two attributes are constants or absent.** INJ is 85 for every player and no injury model reads it. STA is a
   formula of age and position and no fatigue model reads it.
9. **PRC is a copy of AWR for every position except defenders** (`pipeline/ratings.py:558`), so it adds no
   information for offense.

## Limits

- The probe scenarios exercise 10 of the 16 engine-read attributes. AGI, AWR, FMV, KPW, RBK and STR are read by the
  engine but not probed here.
- The table of engine lines is validated by the script, which checks each cited line for the expected token.
  It does not check that the engine uses the value the way the formula describes; only the probes do that.
- The "validation" column says "none in repo" for every row, which was checked by grepping the rating files and
  `docs/RATINGS.md`. It does not establish that no external validation exists.
- The ROADMAP.md referenced by the brief does not exist in this repository or in its history
  (`git log --all -- ROADMAP.md` is empty).

## Reproduce

```
node scripts/rating_audit.mjs --md <out.md> --json <out.json>
```

The script writes the two generated tables. This document places them between the analysis above and the examples
below.
